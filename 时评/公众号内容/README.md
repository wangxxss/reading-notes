# 公众号内容

公众号「哀的代码实验室」的写作与发布工作流。

分工：**我出主意和素材、做最后修改；AI 负责采访、写初稿、挑毛病；脚本负责排版和推送。**
目的是让每篇文章都有只有我能写的东西，避免被平台判为"低创作度内容"。

## 目录结构

```
公众号内容/
├── .claude/skills/wx-write/SKILL.md   写作流程（Claude Code Skill）
├── 写作/风格卡.md                       我的口吻、禁用词、结构禁忌，AI 写稿和终检都以它为准
├── 文章/                               每篇一个目录，见下文
├── scripts/
│   ├── md2wechat.py                    Markdown → 公众号 HTML（固定排版，只用内联样式）
│   ├── cover.py                        生成封面图 images/cover.png
│   ├── check_text.py                   核对加排版标记前后文字是否一字不差
│   └── wx_publish.py                   排版 + 上传图片 + 推送草稿箱
└── tmp/                                预览文件（不入 git）
```

每篇文章 `文章/YYYY-MM-DD-短名/`：

| 文件 | 谁写 | 内容 |
|---|---|---|
| `00-主意.md` | 我 | 一句话的主意 |
| `01-采访.md` | AI 问、我答 | 问题和我的原始回答 |
| `02-初稿.md` | AI | 初稿，留作对比，不再改 |
| `03-终稿.md` | 我 | 从初稿复制，在这里改，发布用这份 |
| `images/` | 我 | 配图、封面 |

## 写一篇的流程

在本目录启动 `claude`：

1. **出主意**：`/wx-write 我想写写……`，AI 会问 3～5 个问题，随口答（语音转文字也行）
2. **出初稿**：AI 按风格卡写初稿，用 `【补充：……】` 标出需要我亲手补的地方
3. **我来改**：改 `03-终稿.md`，补全【补充】、改观点、删掉不像我会说的话
4. **终检**：说"终检"，AI 只列问题和建议，同意哪条才改哪条
5. **排版标注**：AI 给定稿加标题、高亮、提示框、金句、列表等标记，**只加标记不改字**，
   用 `check_text.py` 核对文字一字不差
6. **发布**：生成封面，看预览，确认后推送草稿箱，最后在手机「公众号助手」里发布

旧文章也能单独做第 5 步：把旧文丢给 AI，说"给这篇加排版"。

节奏：每周 2～3 篇，发得太密容易被判同质化。

## 脚本单独使用

```bash
# 生成封面 images/cover.png
python3 scripts/cover.py 文章/2026-11-02-xxx

# 只生成预览（tmp/ 下），不推送
python3 scripts/wx_publish.py 文章/2026-11-02-xxx

# 推送到草稿箱
python3 scripts/wx_publish.py 文章/2026-11-02-xxx --push

# 只做排版转换
python3 scripts/md2wechat.py 某篇.md 输出.html

# 核对两版文字是否一致（忽略排版标记）
python3 scripts/check_text.py 原文.md 03-终稿.md
```

`03-终稿.md` 开头的 frontmatter：

```
---
title: 文章标题
digest: 一句话摘要（也会显示在正文开头的引导框里）
cover_text: 封面大字        # 10 字以内，可用 | 手动换行；不写则用标题
cover_tag: AI 时评          # 可选，封面右上角小标签
cover_style: dark           # 可选，dark（深色，默认）或 light（浅色）
cover: images/cover.png     # 可选，默认就是这个路径；文件不存在则用 config.properties 里的 thumb_media_id
cover_in_body: no           # 可选，默认封面图也放在正文最上面，写 no 则不放
author: 作者                # 可选
---
```

支持的 Markdown 写法：`##` / `###` 标题（一级标题自动编号 PART 01…）、加粗（主色）、`==高亮==`（荧光笔）、
斜体、行内代码、删除线、链接、引用、列表、代码块、表格、单独一行的图片（alt 文字作为图注）、`---` 分隔线，
以及四种提示框：

```
> [!TIP] 蓝色重点
> [!WARN] 红色警告
> [!OK] 绿色正确做法
> [!GOLD] 金句（上下细线，居中大字）
```

## 样式

- 正文样式集中在 `scripts/md2wechat.py` 顶部：主色 `ACCENT` 改一处全篇生效，其余在 `S` 字典里。
- 封面：公众号封面在列表里显示 2.35:1，分享到好友/朋友圈只取中间 1:1，所以封面大字只放中间正方形区域。
  封面同样用 `ACCENT` 主色，和正文统一。

## 配置

- AppID / AppSecret：优先读环境变量 `WX_APPID` / `WX_SECRET`，其次读本目录的 `config.properties`，
  没有则沿用 `../publish/config.properties`。`config.properties` 已在 `.gitignore` 里，不要提交。
- 调用微信接口的机器 IP 需要加到公众号后台的 IP 白名单（报错 40164 就是这个原因）。
- 已上传的图片记录在各文章目录的 `.wx-uploaded.json`，重复推送不会重复上传。

## 注意

- 公众号标题实际可写 64 字左右。推送时必须用 `ensure_ascii=False` 序列化 JSON，
  否则中文被转成 `\uXXXX`，微信按转义后的长度计算，标题很快就超限（脚本已处理）。
- 手动粘贴到公众号编辑器时，用预览页右下角的「复制正文」按钮，不要自己框选复制：
  框选会把浏览器计算的样式（如 `text-align:start`）一起带上，触发公众号的「文字对齐异常」检测，
  还会把预览页的标题一起复制进去。
- 个人号正文里的外链点不开，脚本会把网址以灰色小字附在链接文字后面。
- 正文图片微信只收 jpg/png、单张 1MB 以内；超过的推送时自动用 macOS 自带的 sips 压成 jpg。
- 预览页里的图片已嵌进页面，「复制正文」时会一起带走。
