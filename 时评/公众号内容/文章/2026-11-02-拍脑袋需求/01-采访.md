> 来源：上面的飞书表格。人名已换成角色，发布时注意不要暴露公司、系统和同事信息。

**统计**：有效问题 50 条，其中「需求文档不明确/变更」18 条（36%），「环境问题导致」9 条，「BUG」4 条，「不是问题」2 条，未分类 17 条。50 条里 22 条由我处理。

**典型条目**（问题 → 开发备注 → 最后结论）：

- 登录名大小写：验收要求"大小写不一致不算不通过" → 需求里公司名写了忽略大小写，登录名没写 → 三处登录名统一不区分大小写，需求已补充。
- 二次上传的审核意见：验收说"应该覆盖，不是叠加" → 需求没写追加还是覆盖，开发考虑保留历史备注选了追加 → 按运营要求改成覆盖。
- 身份证人像面/国徽面：验收要求作废人像面时联动作废国徽面 → 上传时是两条附件，没有关联关系，根据人像面找不到国徽面 → 结论：作废人像面时同步作废国徽面。
- 退回备注文案：多条反馈"不应该把比对标准直接写进备注"，要改成"身份证已到期，请重新提供"之类 → 开发备注：需求文档未明确 / 需求未明确说明备注字段要求。
- 附件编号前缀：要求去掉备注里的【附件编号】，同时"合同复审队列需要添加附件编号列" → 前缀可去，加列走需求变更 → 最后又确认"审核中间页无需添加附件编号信息"。
- 邮件推送：验收阶段整段补规则（订单状态、认证公司邮箱名单） → 开发备注：补充规则，目前需求无 → "改动较大，建议走优化需求"。
- 登录名含空格：建议自动去空格 → 补充规则，目前需求无 → 开发反问："烦请产品考虑，针对该场景，需要处理吗？"
- 电子签章授权书：审核通过后要同步上传到电子签章管理系统 → 需求未明确具体要求。
