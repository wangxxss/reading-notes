# 公众号写作工作流

分工：**用户出主意和素材、做最后修改；AI 负责采访、写初稿、挑毛病。** 目的是让每篇文章都有用户独有的内容，避免被平台判为"低创作度内容"。

写作前必须先读 `写作/风格卡.md`，初稿和终检都以它为准。

## 文件组织

每篇文章一个目录 `文章/YYYY-MM-DD-短名/`：

| 文件 | 谁写 | 内容 |
|---|---|---|
| `00-主意.md` | 用户 | 一句话的主意，原样保存 |
| `01-采访.md` | AI 问、用户答 | 问题和用户的原始回答（原话，不改） |
| `02-初稿.md` | AI | 初稿，写完后不再改动，留作对比 |
| `03-终稿.md` | 用户 | 从初稿复制而来，用户在这里改，发布用这份 |
| `images/` | 用户 | 配图、封面 |

## 判断当前阶段

用户给了新主意 → 从第 1 步开始。否则找到用户说的那篇（没说就取 `文章/` 下最新的目录），按已有文件判断进度：缺 `01` 做第 1 步，缺 `02` 做第 2 步，有 `03` 且用户要终检做第 4 步，用户要发布做第 5 步。

## 1. 记主意 + 采访

1. 新建目录，主意原样写进 `00-主意.md`。
2. 查 `文章/` 下最近 7 天的目录数，已有 3 篇及以上就提醒一句：发得太密容易被判同质化。
3. 提 3～5 个问题，一次性列出，挖出只有用户能提供的东西：
   - 具体在什么场景遇到的？当时发生了什么、谁说了什么？
   - 你的观点是什么？和大多数人想的哪里不一样？
   - 有没有亲身经历、数据、截图能当例子？
   - 这件事对你自己有什么影响？
   问题要贴着这个主意问，不要每次都是这几句。
4. 告诉用户：随便答，语音转文字、写得乱都行，不想答的跳过。
5. 用户回答后，问题和回答原样存进 `01-采访.md`。回答太单薄（全是观点、没有一个具体的人和事）就再追问一轮，最多两轮。

## 2. 写初稿

1. 按 `写作/风格卡.md` 写 `02-初稿.md`，开头带 frontmatter：
   ```
   ---
   title: 标题
   digest: 一句话摘要（50 字以内）
   cover_text: 封面大字，10 个字以内，可用 | 换行，要比标题更短更有冲击力
   cover_tag: 封面右上角小标签，如「AI 时评」「技术圈观察」
   ---
   ```
2. 文章骨架来自用户的回答，不要套"钩子 + 三段论 + 金句"的爆款模板。采访里的生动原话直接用。
3. 用 `【补充：……】` 标出 2～4 处需要用户亲手补的地方，不替用户编经历和感受。
4. 排版只用 `scripts/md2wechat.py` 支持的 Markdown 写法（见脚本开头说明），不写 HTML。
   排版要克制：`**加粗**` 和 `==高亮==` 全文合计不超过 6 处，`[!GOLD]` 金句最多 1 个，提示框按需用、不为好看而用。
5. 把 `02-初稿.md` 复制为 `03-终稿.md`，告诉用户去改 `03-终稿.md`：补全【补充】、改观点、删掉不像他会说的话。

## 3. 用户修改

这一步 AI 不动手。用户改完会回来要求终检。

## 4. 终检（只提意见，不重写）

读 `03-终稿.md`，按条列出问题，每条给出原句和建议改法：

1. 没补的 `【补充】`
2. 风格卡禁用词和结构禁忌的命中
3. 错别字、病句、前后矛盾、逻辑跳跃
4. 3 个备选标题（不夸张、不当标题党）和 1 句摘要

用户同意哪条才改哪条。顺便对比 `02` 和 `03`：用户删掉或新加的典型说法，问用户要不要补进风格卡。

## 5. 排版标注（只加标记，一个字不改）

文字定稿后、发布前做。也可单独用于旧文章：用户给一篇旧文，建 `文章/` 目录，原文存 `原文.md`，复制为 `03-终稿.md` 再标注。

1. 先备份：`cp 03-终稿.md .排版前.md`
2. 在 `03-终稿.md` 上只加排版标记：
   - 分节：`/01/`、加粗的小标题行 → `##` 标题（用原文文字，不新写标题）
   - 对话、原话 → `>` 引用
   - 全文的核心论点 → `> [!TIP]`；风险、副作用 → `> [!WARN]`；建议、结论 → `> [!OK]`
   - 最有力的一句 → `> [!GOLD]`，全文只用一次
   - 值得划重点的半句话 → `==高亮==`；关键词 → `**加粗**`，两者合计不超过 6 处
   - 并列的几句（分号、换行隔开的排比）→ `-` 列表
   - 英文专有名词、命令、代码 → 行内代码
   - 原来过长的整段加粗，去掉加粗或改为提示框，避免整段变成蓝字
   - 收尾段前可加 `---`
3. 核对文字：`python3 scripts/check_text.py .排版前.md 03-终稿.md`。报不一致就改回去，直到输出"文字完全一致"。
4. 删除 `.排版前.md`，生成预览给用户看。

## 6. 发布

1. 用户没有自己的封面时，生成封面：`python3 scripts/cover.py 文章/<目录>`，读 `images/cover.png` 给用户看。
   用户不满意就改 `cover_text` / `cover_tag` / `cover_style`（dark 或 light）重新生成。
2. 生成预览：`python3 scripts/wx_publish.py 文章/<目录>`，把预览文件路径告诉用户，让用户在浏览器里看一眼。
3. 用户确认后再推送：`python3 scripts/wx_publish.py 文章/<目录> --push`。推送前必须得到用户明确同意。
4. 推送成功后提醒用户：到手机「公众号助手」里检查草稿再发布。
